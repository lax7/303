ICMP & the Redirect Attack

How routers use ICMP to correct each other's routing — and how an attacker forges that same message to quietly become a man-in-the-middle on the victim's traffic.

What is ICMP The header Message types Redirect message The attack Why it works

01What ICMP is for

IP moves packets but never reports back. ICMP is the thin control layer that lets routers and hosts send each other diagnostics and error notices about that delivery.

ICMP (Internet Control Message Protocol) rides inside IP, as protocol number 1. It carries no user data of its own — only control signals: "that host is unreachable," "your packet's time ran out," "are you alive?" (ping), and the one this lab abuses, "you should send this to a different router."

Because ICMP lives in the IP payload, the Protocol field of the outer IP header is set to 1 so the receiver knows to hand the payload to its ICMP handler rather than to TCP or UDP.

02Anatomy of the header

Every ICMP message opens with the same 8 bytes. The first three fields are fixed; the fourth — "rest of header" — changes meaning depending on the Type.

Type · 1 byte Code · 1 byte Checksum · 2 bytes Rest of header · 4 bytes

Type & Code

Type names the message category (e.g. 8 = echo request). Code is a sub-reason within that type. Together they tell the receiver exactly what happened.

The data section matters

Error messages echo back the IP header + 8 bytes of the offending packet. That quoted packet is how the sender — and any security check — knows which flow the message refers to.

03Common message types

A handful of types cover almost everything you'll see. Redirect — Type 5 — is the one with the Gateway Address field in its "rest of header."

TypeNameWhat it says

8Echo RequestThe ping itself: "are you there?"

Redirect codes For Type 5, the Code narrows it down: 0 redirect for the network, 1 for the host, 2 for ToS+network, 3 for ToS+host. The lab uses a host redirect.

04Inside a Redirect packet

A legitimate redirect comes from a router. Its "rest of header" is a Gateway Address — the better router to use — and its data section quotes the packet that triggered it.

The forgery mirrors this exactly. In Scapy the attacker builds a packet whose outer IP claims to be from the real router, whose ICMP layer is the redirect pointing at the malicious router, and whose embedded ip2 is a copy of the packet the victim really sent:

#!/usr/bin/python3
from scapy.all import *

# Outer IP: pretend to be the real router (10.9.0.11)
ip   = IP(src='10.9.0.11', dst='10.9.0.5')       # dst = the victim
icmp = ICMP(type=5, code=1)                    # redirect, host
icmp.gw = '10.9.0.111'                          # ← malicious router

# Embedded packet that "triggered" the redirect
ip2  = IP(src='10.9.0.5', dst='192.168.60.5')   # victim → target

send(ip/icmp/ip2/ICMP())
Routing cache, not routing table A redirect never edits the routing table. It writes a temporary entry into the routing cache, which overrides the table until it expires. Check it with ip route show cache and clear it with ip route flush cache.

05The attack, step by step

Goal: when the victim (10.9.0.5) sends to 192.168.60.5, make it route through the attacker-controlled router (10.9.0.111) instead of the real one (10.9.0.11).

06Why it works — and the catches

ICMP has no authentication. A redirect is trusted simply because it arrives. But the kernel does one sanity check, and the lab's questions probe its limits.

  • No authentication. Nothing in ICMP proves the sender really is a router, so a spoofed source IP is enough to be believed.
  • The sanity check. The kernel only accepts a redirect if the embedded ip2 matches a packet the victim actually sent (right type and destination). So the victim must have real traffic to 192.168.60.5 in flight — otherwise the redirect is ignored.
  • Countermeasure. Ubuntu normally drops redirects (accept_redirects=0); the lab turns it on to make the attack possible.
  • Gateway must be on the LAN. A redirect can only point to a router on the same local network — pointing it at a remote or non-existent host fails (Lab Q1 & Q2).
From redirect to MITM — Task 2 Once traffic flows through 10.9.0.111, disable its IP forwarding (sysctl net.ipv4.ip_forward=0) and run a sniff-and-spoof program. Capturing only the victim→target direction, it rewrites the payload (e.g. replacing your name with A's of equal length to keep TCP sequence numbers intact) and re-sends it.
