Sequence & Acknowledgment Numbers

TCP numbers bytes.

Host A and Host B each have their own independent sequence and ACK numbers, to track the bytes they send and acknowledge the bytes they receive.

SEQ: “here is where my data starts”

The sequence number is the number of the first byte in this segment. The next segment from the same host starts right after the last byte of this one.

next SEQ = this SEQ + bytes sent

ACK: “I want this byte next”

The acknowledgment number is the next byte I expect from the other side. It is cumulative: it covers everything received so far.

ACK = their SEQ + their bytes

Special cases

A segment with 0 bytes (a pure ACK) does not move the sender’s SEQ. SYN and FIN each use up exactly one sequence number, even with no data.

SYN or FIN → SEQ + 1

Picture A’s byte stream

Segment 1SEQ 1001200 bytes
Segment 2SEQ 1201200 bytes
Not sent yet…

Segment 1 carries 200 bytes, numbered 1001 to 1200. So segment 2 starts at 1201. Once B has both segments, B tells A which byte it wants next.
