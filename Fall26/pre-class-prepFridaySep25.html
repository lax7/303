Part 1 — Linux

A quick tour of chmod4 points

Every file and directory on Linux carries permissions for three classes of user: the owner, the group, and others (everyone else). Each class can be granted three actions:

rread — view the file / list a folder. Value 4
wwrite — change the file / add & remove in a folder. Value 2
xexecute — run the file / enter a folder. Value 1

Reading ls -l

Run ls -l and the first column shows the permissions as a 10-character string:

-rwxr-xr-- 1 alice staff … notes.txt ^└┬┘└┬┘└┬┘ │ │ │ └─ others: r-- (read only) │ │ └───── group : r-x (read + execute) │ └───────── owner : rwx (read + write + execute) └──────────── type : - (- file, d directory)

Two ways to set permissions

Symbolic — say who (user, group, others, all), then + add, - remove, or = set exactly, then the letters:

$ chmod u+x script.sh # give the owner execute$ chmod go-w notes.txt # remove write from group + others$ chmod a=r shared.txt # everyone: read only

Numeric (octal) — add the values (r=4, w=2, x=1) for each class, in the order owner-group-others:

OctalSymbolicMeaning
755rwxr-xr-xOwner full; group & others read + run (typical script/folder)
644rw-r--r--Owner read+write; everyone else read (typical file)
600rw-------Owner read+write; no one else (private file)
700rwx------Owner full; no one else (private folder/script)
$ chmod 644 notes.txt # same as u=rw,go=r

Part 2 — Network security lab

ARP cache poisoning6 points

Step 0 — watch the assigned recording first.
ARP Cache Poisoning — Meeting Recording (Sep 23) ↗  (opens in SharePoint — sign in with your ERAU account)

What you're doing (in one paragraph)

Hosts on a LAN use ARP to map IP addresses to MAC addresses, and they update their cache from incoming ARP messages without verifying them — including unsolicited ARP requests (opcode 1), whose sender fields a host will happily record. In a poisoning attack you send forged ARP requests so a victim and the gateway each store the attacker's MAC for the other's IP. Watch the video, then repeat the attack in your own virtual environment using your Python script (Scapy, op=1), and confirm it by inspecting the poisoned host's ARP cache before and after.

Hand in — 6 points

  • 📸 Screenshot of your Python code (the Scapy poisoning script)  (2)
  • 📸 Before — the poisoned host's ARP cache (arp -a) showing the gateway's real MAC  (2)
  • 📸 After — the same host's ARP cache showing the gateway IP now mapped to the attacker's MAC  (2)

Run everything against the machine you're poisoning — the before/after must be that same host's ARP cache so the changed MAC is visible. Follow the exact steps your video/instructor gives; this checklist is the shape of the task, not a substitute for the assigned method.
